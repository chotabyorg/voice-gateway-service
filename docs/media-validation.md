# Standalone media acceptance — 2026-10-13

The local media hardening work is implemented and checked without Docker,
provider credentials, public telephony, production routing or a Conversation
implementation. This is evidence for the standalone media boundary, not live
telephony acceptance or an approved Voice/Conversation protocol.

## Reproduce natively

From the repository with Python 3.11 and `requirements-dev.txt` installed:

```sh
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m compileall -q voice_gateway tests scripts
python -m pytest -q
python -m scripts.media_soak --rounds 120 --concurrency 8 --output media-soak.json
```

On Windows use `.venv\Scripts\python.exe`; on POSIX use `.venv/bin/python`.
The soak runner starts and stops its own ephemeral `127.0.0.1` AudioSocket
listener. It neither reads provider keys nor contacts external services. Only
numeric diagnostics are written; PCM and transcripts are never saved.

## Recorded loopback run

Python 3.11.0, Windows build 26100; 120 rounds of eight concurrent calls in
120.71 seconds. The input is synthetic PCM16/8 kHz, with varied packet sizes,
fragmented handshakes and injected 25 ms producer stalls. STT and TTS are local
fakes with 30 ms and 40 ms delays. The local Conversation seam returns a fixed
fixture; there is no AI latency or network provider in these measurements.

| Retained allocation range in final quarter | 21,870 bytes |

The runner asserts resource pairing, absence of per-call tasks after each round,
expected terminal playback outcomes and clean shutdown. Its bounded diagnostic
deques and per-round memory samples contribute to retained allocations, so the
allocation delta is not a direct media leak estimate. This two-minute socket
run and accelerated 30-minute audio test are different tests, not a 30-minute
wall-clock soak.

Playback uses a high-resolution monotonic performance counter; the Windows
scheduler, tracing and concurrent work still cause substantial frame variation.
These numbers are a reproducible local baseline, not a production jitter SLA.
AudioSocket has no proof of what the caller actually heard; completed playback
only means all generated bytes were handed to the transport. Timing events based
on the process monotonic clock also have the host clock's resolution limits.

## Remaining coordinated acceptance

- Real Russian/Belarusian recognition accuracy, names/numbers, voice naturalness
  and model availability require an approved speech corpus and provider run.
  Synthetic PCM and mock HTTP do not establish WER or perceptual speech quality.
- Real echo, upstream buffering, heard interruption and deployment-host latency
  require the chosen PBX/provider path and controlled inbound call.
- The platform team supplies the frozen Voice/Conversation contract and exact
  implementation after Goal5 acceptance. Voice retains its local seam until then.
- After implementation and readiness evidence, controlled live acceptance is
  limited to `+375173820015`. Pool routing and VOICE activation remain gated;
  `RESERVED` is only a reservation. See [`artem-handoff.md`](artem-handoff.md).

No new Conversation, ManagedTurn, Message, AgentTurn, Business/CRM, shared
playback semantics or GitOps changes are needed or included in this local work.

## Pre-merge review — 2026-10-15

Review found that a timeout context spanning an async-generator yield could
cancel consumer playback between reads; when later reads ran in another task,
it could instead stop enforcing the stream deadline. Both failure modes were
reproduced before fixing HTTP TTS and decoder reads to use one absolute deadline
with a separate timeout scope per awaited operation. Buffered chunks cannot
bypass an expired deadline. New regressions cover both task arrangements and
actual decoder child/pipe cleanup. The complete suite now passes **154 tests**;
the local soak record above remains the 2026-10-13 baseline.
